NETWORK X Companion — Privacy Policy

Effective November 7, 2026. Applies to the NETWORK Chrome companion and its NETWORK API integration.

What the companion does

The companion lets you read NETWORK feeds, post, like and reply using your NETWORK account, and optionally show public NETWORK context on X/Twitter. It does not execute trades, connect wallets, request seed phrases or private keys, or automate X posting, likes or follows.

Sign-in and storage

X authorization opens in a top-level Chrome authentication window. NETWORK receives the X profile information needed for account ownership linking. X provider access tokens are discarded after the profile lookup; the extension never receives them or an OAuth client secret.

The companion uses a one-time, PKCE-bound authorization code (60-second validity), then a revocable NETWORK extension session valid for one hour. The session is kept only in Chrome's in-memory storage.session, restricted to trusted extension contexts. It is not an httpOnly cookie; trusted packaged extension code can access it, but content scripts and X pages cannot. Browser restart, extension reload or disable clears this memory. The server stores only a token hash. Logout revokes the current companion session and clears local credentials; offline revocation cannot be confirmed until connectivity returns, and server expiry still applies. Your separate NETWORK website session is not logged out.

Your contextual-card preference is saved locally across browser restarts. No session credentials are stored in persistent local or sync storage.

Optional X page context

Contextual cards are off until you enable them. When enabled, the content script reads the visible post's author handle, first cashtag and first Solana-like address to query NETWORK's public records. Only those extracted references are sent to NETWORK, not the full tweet text, images, cookies, browsing history or private X messages. An address mention is not proof of a token. Cashtags are ambiguous. No matching record is not a safety assessment.

Inline cards use public NETWORK records only, even while you are signed in. Your private NETWORK feed and member-only content are never inserted into X pages.

Posts and server processing

Posts, replies, likes and audience selections you explicitly submit are sent to NETWORK and retained under the same account and privacy rules as the website. Member-only information is permission-filtered by the server. NETWORK's hosting and network providers process the requests needed to deliver the service. Request metadata such as IP address, path and timing may be present in infrastructure logs. The application suppresses authorization query strings in its access log; it does not log session tokens. One-time authorization codes appear only in the intercepted redirect, not reusable tokens.

Use, sharing and control

These data are used to provide the companion features, authenticate requests, enforce permissions and abuse limits. This extension contains no advertising, tracking analytics or sale of data. It does not send detected X references to advertising services. X handles its own OAuth service under its policies. NETWORK uses its configured hosting infrastructure; operators must maintain this policy if processing changes.

You can disable context at any time, log out, remove the extension, and manage or delete your NETWORK account in the full website's Settings. Server authorization requests and sessions expire and are cleaned up on subsequent authorization operations; your NETWORK posts follow account retention/deletion rules. Contact the NETWORK platform administrator through the NETWORK service for privacy or account assistance. Do not send credentials or wallet secrets.
